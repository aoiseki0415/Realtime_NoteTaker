# Realtime NoteTaker: 合意済み仕様

この文書は、実装前に合意した要件を記録する。対象は、このMac Air上だけで利用する個人用macOSアプリである。

## 1. アプリの位置づけ

- Codexは開発・保守に使う。会議中に動作する実行主体は独立したmacOSアプリとする。
- macOSネイティブのSwiftUIアプリとして実装する。
- 表示・文字起こし・議事録の主言語は日本語に固定する。

## 2. 開始前の設定

会議を開始する前に、アプリ内で以下を入力または選択する。

| 項目 | 内容 |
| --- | --- |
| 会議名 | 必須入力。議事録ファイル名にも使う。 |
| 利用場面 | `対面会議`、`オンライン会議`、`動画視聴`。 |
| 自分以外の人数 | 話者分離の目安・品質確認に使う。話者数を厳密に固定するものではない。 |
| 音声機器 | `Mac本体`または`イヤホン・外部機器`を選び、実際のマイクデバイスを確認する。 |
| 会議アプリ | オンライン会議時にZoom、Microsoft Teams、Google Meet、その他を選択する。 |
| システム音声の対象 | 実際に取得するアプリまたはウィンドウをmacOS標準の選択画面で確認する。 |
| テンプレート | 標準会議、研究・プロジェクト進捗、動画視聴・講義メモから選ぶ。 |
| 同意確認 | 録音・文字起こしと、OpenAI APIへの音声・テキスト送信を確認する。 |

## 3. 音声取得

### 音声経路

| 場面 | マイク系 | システム音声系 |
| --- | --- | --- |
| 対面会議 | 使用する | 使用しない |
| オンライン会議 | 使用する。自分の発言として扱う。 | 使用する。相手側の発言として扱う。 |
| 動画視聴 | 使用しない | 使用する。動画音声として扱う。 |

- マイク系とシステム音声系は混ぜずに扱う。
- システム音声はScreenCaptureKitで選択した対象から取得する。
- マイクは選択した内蔵・イヤホン・外部入力デバイスから取得する。
- スピーカー利用時にシステム音声がマイクへ回り込んだ場合は、近接した重複発話を検出して議事録への重複記載を避ける。
- イヤホンの切断など、入力デバイスの変更・喪失を検知した場合は警告する。

### オンライン会議アプリ

- ZoomとMicrosoft Teamsは、起動中の対応アプリを候補として表示する。
- Google Meetはブラウザ上で動作するため、実際に使用しているブラウザを選択する。
- 会議アプリの選択はプリセットであり、開始時には取得対象を必ず確認する。
- ブラウザの別タブなど不要な音声が混ざらないよう、利用者に注意を表示する。

## 4. 文字起こしと話者分離

- OpenAIの話者分離対応文字起こしモデルを利用する。
- 文字起こしは音声取得中に継続して行う。
- マイク系とシステム音声系は独立して文字起こしし、取得時刻を基準に統合する。
- 対面会議では、マイク系を話者分離する。
- オンライン会議では、マイク系は`自分`として扱い、システム音声系を話者分離する。
- 動画視聴では、システム音声系を話者数1の前提で扱う。
- 話者人数は話者ラベルの参考と、検出結果の大きな乖離を確認するために使う。厳密な人数一致を要求しない。

## 5. ローカル議事録の更新

- 文字起こし結果を基に、30秒ごとにローカル議事録を更新する。
- 同じ更新で、重要発話の選定と構造化したまとめの更新を行う。
- 会議中はローカルアプリで閲覧・更新し、Google Docsなどの外部文書へ同期しない。

### 構造化したまとめ

- 議事録の上部に配置する。
- 発言者名ではなく、内容を中心に記録する。
- 選択されたテンプレートに従って更新する。

初期テンプレート:

| テンプレート | 見出し |
| --- | --- |
| 標準会議 | 会議の目的、主な議論、決定事項、ToDo、未解決事項・次回確認 |
| 研究・プロジェクト進捗 | 背景・目的、現在の進捗・共有事項、検討した内容、決定した方針、実施タスク、課題・保留事項 |
| 動画視聴・講義メモ | 内容の要約、重要な論点・知見、キーワード、今後確認したいこと、自分のToDo・メモ |

### 重要発話ログ

- 議事録の下部に配置する。
- 時刻、話者ラベル、重要と判断した発話本文を時系列で記録する。
- 全発話の完全ログではない。30秒ごとの整理で重要と判断した発話だけを残す。

## 6. 保存とGitHub連携

- 会議終了時に、ローカル議事録からMarkdownを生成する。
- 保存先は、このプロジェクトと同じGitHubリポジトリ `aoiseki0415/Realtime_NoteTaker` とする。
- 保存パスは `議事録管理/YYYY/MM/YYYY-MM-DD_HHMM_会議名.md` とする。
- 議事録は自動でコミット・プッシュする。
- GitHub保存に失敗してもローカルの議事録を保持し、再送できるようにする。
- GitHubへ送るのは構造化したまとめと重要発話ログだけである。
- リポジトリはprivateで運用する。

## 7. 一時データとセキュリティ

- 原音声は保存しない。音声は文字起こしのために必要な間だけメモリ上で扱う。
- 一時的な全転写は会議終了までローカルに暗号化して保持する。
- 終了時に削除確認を表示する。利用者が削除を選ぶまで削除しない。
- 削除時は暗号鍵も破棄し、復号できない状態にする。
- OpenAI APIキーとGitHub認証情報はMacのKeychainに保存し、リポジトリ・議事録・ログへ書き込まない。
- APIキーやパスワード形式など、明確な秘密情報はGitHub保存前に自動マスクする。
- デバッグログやクラッシュレポートには会議本文を残さない。
- OpenAIへの送信を含むことを、開始前の同意確認に明記する。

## 8. 終了と障害時の動作

| 状態 | 動作 |
| --- | --- |
| 正常終了 | Markdown生成、GitHubへの自動保存、一時転写の削除確認を順に行う。 |
| GitHub保存失敗 | ローカル議事録を保持し、再送可能にする。 |
| アプリが予期せず終了 | 次回起動時に未完了会議を検出し、再開・書き出し・削除を選べるようにする。 |

## 9. 初期検証

実機で、Zoom、Microsoft Teams、Google Meetをそれぞれ検証する。Google Meetは、使用ブラウザ、別タブ音声、イヤホンの有無による混入を重点的に確認する。
